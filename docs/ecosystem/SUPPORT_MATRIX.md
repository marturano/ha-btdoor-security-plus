# Ecosystem support matrix

Status vocabulary:

- **Implemented** — present in the current runtime.
- **Foundation** — architecture and documentation defined, runtime adapter not yet delivered.
- **Planned** — roadmap item without a completed adapter contract.

| Domain | Product family | Current status | Target roadmap | Notes |
|---|---|---:|---:|---|
| Platform | BTicino umbrella ecosystem | Foundation | 2.0–2.9 | Capability and adapter foundation across product families |
| Video door entry | BTDoor Security+ compatible endpoint | Implemented | 1.x / 2.6 | Access actions, SIP/voice foundation, events, diagnostics and media helpers |
| Video door entry | Classe 300EOS / Classe 100X generalized adapter | Foundation | 2.6 | Requires verified protocol/device matrix |
| Electrical | Home + Control | Foundation | 2.0–2.1 | Account/home/room/module model defined |
| Electrical | Living Now with Netatmo | Foundation | 2.1 | Capability mapping defined |
| Electrical | Livinglight with Netatmo | Foundation | 2.1 | Capability mapping defined |
| Electrical | MatixGO with Netatmo | Foundation | 2.1 | Capability mapping defined |
| Energy | BTDIN | Foundation | 2.2 | Energy semantics and HA surface defined |
| Climate | Smarther / Smarther2 | Foundation | 2.3 | Climate model defined |
| Security | Home + Security / Netatmo security | Foundation | 2.5 | Privacy and incident boundaries defined |
| MyHOME | Gateway and bus domains | Foundation | 2.7 | Requires gateway/protocol matrix |
| Environment | Netatmo weather and indoor modules | Planned | 2.4 | Not implemented in current runtime |

This matrix is normative. Product-family documents may not claim a higher support level than this file without a release change and validation update.
