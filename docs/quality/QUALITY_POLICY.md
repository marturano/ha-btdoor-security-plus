# Quality Policy

All Quality Reviews are versioned project artifacts. A review without written evidence is not complete.

## Required review families

Design, self/code, tests, security, performance, benchmark, UX, translation, compatibility, documentation, automation assets, release readiness and final QA.

## Minimum evidence

Scope, release, reviewer/process, checks, evidence links, findings, severity, corrective action, owner, status, exceptions, final outcome and closure date.

## Consolidated release-quality principles

Runtime safety and identity stability take priority over feature velocity. Physical gate actions require explicit intent and must never be blindly retried. Source, documentation, manifest, runtime version and release artifacts must agree. Real-device claims require recorded real-device evidence.

Mandatory evidence includes source integrity, Home Assistant/HACS checks where available, regression and safety tests, documentation consistency, translation integrity, compatibility review and a reproducible package with checksum.
