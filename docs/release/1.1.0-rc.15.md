# BTDoor Security+ 1.1.0-rc.15

## Repository Governance & Integrity Foundation

RC.15 Phase 1 introduces the Project Governance Charter, Repository Integrity Suite, Roadmap Integrity Check, Definition of Ready/Done, and Zero Knowledge Loss continuity controls.

### Runtime impact

No functional runtime behavior is intentionally changed. Integration version metadata is advanced to RC.15.

### Roadmap correction

The duplicate `4.3` identifier is resolved: Adaptive Home Experience remains 4.3 and Documentation Platform becomes 4.4.

### Validation

Run `python tools/check_repository_integrity.py` and the focused RC.15 tests before packaging.


## Phase 2 — Architecture Foundation

The architecture set is now canonical and validated. New documents cover configuration entries, data flow, module boundaries, device, event and notification models. Two blocking repository gates validate architecture coverage and Mermaid structure.

## Phase 3 — Ecosystem Foundation

The ecosystem documentation now defines a truthful support matrix, canonical capability model, adapter boundary, discovery and identity rules, and complete BTicino/Netatmo product-family contracts. No broad product adapter is claimed as implemented.

## Phase 4 — AI Platform Foundation

The repository now defines a provider-neutral AI capability layer, runtime orchestration contract, provider matrix, privacy boundary, local-first strategy and normalized automation/event model. OpenAI, Claude, Gemini, Amazon Rekognition and local providers remain architectural targets until adapters and conformance tests are implemented.

## Phase 5 — API Foundation

The current Home Assistant entity, action and event surfaces are now documented as explicit public contracts. Security, errors, versioning, Alexa/Alexa+ and Google Assistant exposure boundaries are covered. REST and WebSocket remain planned and are not claimed as implemented.

## Pre-Phase 7C repository hygiene audit

The canonical package was audited before Phase 7C. Transient coverage state, empty work directories, generated Python caches and a nested release ZIP/checksum were removed from the active repository. Historical binary artifacts were preserved in a separate companion archive. No runtime source was changed. The Quality Scale remains Gold, while the Release Decision Engine remains blocked pending exact-package external and target evidence.

## Approval semantics

Release Readiness `PASS` confirms package-level readiness checks only; Final approval remains `BLOCKED` until the Release Decision Engine returns `APPROVED`.
