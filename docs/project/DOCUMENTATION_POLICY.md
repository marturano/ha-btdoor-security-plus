# Project Documentation Policy

Documentation is a release artifact, not a post-release task. Every change must assess all affected areas: user, developer, API, architecture, governance, compatibility, translations, security, quality, benchmarks, release, automation assets, repository operations and continuity.

Documents must state status, scope, applicable version, last review date and authoritative replacement when superseded. Superseded documents are consolidated into their canonical replacement and then removed from active packages; unique provenance is recorded in the Engineering Notebook and release documentation.
